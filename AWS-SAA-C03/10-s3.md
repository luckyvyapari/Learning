# 10 — Amazon S3 (Core)

"Infinitely scaling" object storage. Use cases: backup, DR, archive, hybrid storage, app/media hosting, data lakes, software delivery, static websites.

## Buckets & Objects

| Concept | Rules |
|---|---|
| **Bucket** | Created in a **region** (S3 looks global but isn't). Name is **globally unique** (shared global namespace) |
| Naming | No uppercase, no underscore, not an IP, start with lowercase letter/number, not prefix `xn--`, not suffix `-s3alias` |
| **Object key** | Full path = **prefix + object name** (`my_folder1/another_folder/my_file.txt`). **No real directories** — just keys with slashes |
| Object size | Max **50 TB**. **> 5 GB must use multi-part upload** |
| Extras | Metadata (key/value), **Tags** (up to 10; for security/lifecycle), **Version ID** |

## Security (summary — details in file 12)

| Type | How |
|---|---|
| User-based | IAM policies |
| Resource-based | **Bucket policies** (bucket-wide, **cross-account**), Object ACL, Bucket ACL (ACLs can be disabled) |

Access allowed if **IAM allows OR resource policy allows**, AND **no explicit deny**.

**Bucket policy uses**: grant public access · force encryption at upload · cross-account access.

| Who | Use |
|---|---|
| Public visitor | Bucket policy |
| IAM user | IAM policy |
| EC2 instance | **IAM Role** |
| Other AWS account | Bucket policy |

**Block Public Access** settings: prevent company data leaks; leave on if bucket never public; settable at **account level**.

## Static Website Hosting

URL: `http://bucket.s3-website-<region>.amazonaws.com`. **403 Forbidden** → bucket policy doesn't allow public reads.

## Versioning

- Enabled at **bucket level**; same key overwritten → new version (1, 2, 3…)
- Best practice: protects against unintended deletes, easy rollback
- Objects uploaded before versioning have version **`null`**
- **Suspending versioning does NOT delete old versions**

## Replication (CRR & SRR)

- **Versioning required on source AND destination**
- **CRR** (cross-region): compliance, lower latency, cross-account
- **SRR** (same-region): log aggregation, prod↔test live replication
- Buckets can be in different accounts; **asynchronous**; needs IAM permissions
- Only **new** objects replicate after enabling; existing ones via **S3 Batch Replication** (also failed objects)
- Deletes: **delete markers** can be replicated (optional); **deletes with version ID are NOT replicated** (avoid malicious deletes)
- **No chaining**: A→B→C does not copy A's objects to C

## Storage Classes

Move manually or with **Lifecycle rules**.

| Class | Availability | AZs | Min duration | Min size | Use |
|---|---|---|---|---|---|
| **Standard** | 99.99% | ≥3 | none | none | Frequent access, big data, mobile/gaming, content |
| **Standard-IA** | 99.9% | ≥3 | 30 d | 128 KB | DR, backups; rapid access when needed |
| **One Zone-IA** | 99.5% | **1** | 30 d | 128 KB | Secondary backups, re-creatable data; lost if AZ destroyed |
| **Glacier Instant Retrieval** | 99.9% | ≥3 | 90 d | 128 KB | ms retrieval, accessed ~once a quarter |
| **Glacier Flexible Retrieval** | 99.99% | ≥3 | 90 d | 40 KB | Expedited 1–5 min, Standard 3–5 h, Bulk 5–12 h (free) |
| **Glacier Deep Archive** | 99.99% | ≥3 | **180 d** | 40 KB | Long-term; Standard 12 h, Bulk 48 h |
| **Intelligent-Tiering** | 99.9% | ≥3 | none | none | Auto-tiers by usage; small monitoring fee; **no retrieval fees** |

**Durability**: **99.999999999% (11 9s)** for all classes (lose 1 object per 10,000,000 every 10,000 years). Availability varies by class.

**Intelligent-Tiering tiers**: Frequent (default) → Infrequent (30 d) → Archive Instant (90 d) → Archive Access (optional, 90–700+ d) → Deep Archive (optional, 180–700+ d).

### S3 Express One Zone
Single-AZ, **Directory Bucket**, 100,000s req/s with single-digit ms latency, up to 10x faster / 50% cheaper than Standard, 99.95% availability. Co-locate with compute. For AI/ML training, HPC, financial modeling; works with SageMaker, Athena, EMR, Glue.

## Exam Hints

- Data you can recreate / secondary copy → **One Zone-IA**
- Unknown/changing access pattern → **Intelligent-Tiering**
- Archive with ms access → **Glacier Instant**; cheapest long-term → **Deep Archive**
- Objects > 5 GB → multi-part upload
- Replication needs versioning; not retroactive
